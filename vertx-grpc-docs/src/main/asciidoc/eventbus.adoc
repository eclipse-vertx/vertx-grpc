[[grpc-eventbus]]
== gRPC EventBus transport

The gRPC event bus transport allows gRPC services to communicate over the Vert.x EventBus instead of HTTP.

The transport supports both protobuf and JSON wire formats.

NOTE: this module is in tech preview in Vert.x 5.2

=== Using the EventBus transport

To use the event bus transport, add the following dependency:

[tabs]
====
pom.xml::
+
[source,xml,subs="+attributes"]
----
<dependency>
  <groupId>io.vertx</groupId>
  <artifactId>vertx-grpc-eventbus</artifactId>
  <version>${maven.version}</version>
</dependency>
----

build.gradle::
+
[source,groovy,subs="+attributes"]
----
dependencies {
  compile 'io.vertx:vertx-grpc-eventbus:${maven.version}'
}
----
====

=== Configuration

Both the client and server can be configured with options.

==== Client options

The {@link io.vertx.grpc.eventbus.EventBusGrpcClientOptions} configures the client endpoint:

[source,java]
----
{@link examples.GrpcEventBusExamples#clientOptions}
----

- `pingInterval`: how often the client pings server endpoints it holds streams with (default: 30 seconds).
- `pingTimeout`: how long a server may go without acknowledging a ping before its streams are terminated (default: 60 seconds)
- `initialWindowSize`: the flow control window for inbound messages, counted in messages (default: 64).

==== Server options

The {@link io.vertx.grpc.eventbus.EventBusGrpcServerOptions} configures the server endpoint:

[source,java]
----
{@link examples.GrpcEventBusExamples#serverOptions}
----

- `enabledFormats`: the set of wire formats the server accepts (default: protobuf and JSON). A request using a format outside this set is rejected with `UNIMPLEMENTED`.
- `maxPingTimeout`: the longest ping timeout the server honours from a client (default: 2 minutes). A client that advertises a longer timeout, or none at all, is held to this value.

=== Closing

Both client and server should be closed when no longer needed. Closing unregisters the event bus consumers and terminates any in-flight streams.

=== Clustering

The event bus transport works transparently over a clustered Vert.x event bus. No special configuration is needed: the same server
and client API applies. The event bus handles routing and load balancing across cluster nodes.

=== Service proxy compatibility

The event bus transport is an evolution of Vert.x service proxies, its design cares about compatibility with service proxies:

Event bus gRPC server accepts service proxies request and treat them as unary calls carrying a JSON payload: a gRPC service
is registered under the service fully qualified name, e.g. `examples.grpc.Greeter`, a method is called passing the gRPC method name
as `action` header.

Event bus gRPC client sends unary calls carrying a JSON payload compatible with a service proxy handler, likewise a client
calls a service using the gRPC service fully qualified name and set the gRPC method name as `action` header.

=== Protocol

The latest version of the protocol is documented https://github.com/eclipse-vertx/vertx-grpc/blob/main/vertx-grpc-eventbus/README.md[here].
